# SpecChain 部署说明

## 1. 部署边界

SpecChain 首版使用 SQLite，并在同一容器内按需启动轻量调度器以及相互隔离的 AI、Playwright CLI 和测试执行子进程。部署时必须满足：

- 只运行一个 SpecChain 应用容器。
- 持久化 `/app/data`。
- 为 Chromium 提供至少 1 GB 共享内存。
- 通过反向代理提供 HTTPS。
- 允许服务通过 HTTPS 访问 `api.github.com` 和 `gitee.com`。
- 允许服务访问管理员配置的 OpenAI 兼容模型 Base URL。
- 仅允许内部可信用户访问。

当前实现不适用于 Serverless、只读文件系统、多实例横向扩容或不可信脚本执行场景。

## 2. 首次部署

复制环境变量模板：

```powershell
Copy-Item .env.example .env
```

生成 32 字节加密密钥：

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

至少修改以下配置：

```dotenv
ADMIN_USERNAME="admin"
ADMIN_PASSWORD="请替换为至少8位的安全密码"
APP_ENCRYPTION_KEY="请填入刚才生成的随机密钥"
SESSION_COOKIE_SECURE="true"
AI_TASK_CONCURRENCY="2"
BROWSER_TASK_CONCURRENCY="2"
```

`AI_TASK_CONCURRENCY` 控制生成 US 和自然语言测试用例的并发数；`BROWSER_TASK_CONCURRENCY` 共同控制 AI 自动化脚本生成与测试用例执行的并发数。两者取值范围均为 `1～16`，默认值为 `2`。浏览器任务会同时占用 Chromium、内存和 CPU，应根据容器资源保守调整。

构建并启动：

```powershell
docker compose up --build -d
docker compose ps
docker compose logs --tail 100 specchain
```

容器健康后访问服务，使用初始管理员登录并立即确认项目配置。

## 3. HTTPS 反向代理

反向代理需要：

- 将请求转发到容器的 3000 端口。
- 保留 `Host`、`X-Forwarded-For` 和 `X-Forwarded-Proto` 请求头。
- 为运行日志轮询接口设置不短于 60 秒的上游超时。
- 使用 HTTPS 时将 `SESSION_COOKIE_SECURE` 设置为 `true`。

平台没有内置 TLS 终止能力，证书应由现有网关或反向代理管理。

## 4. 数据与备份

以下内容都位于 Docker 卷 `specchain-data`：

- SQLite 数据库。
- Playwright 临时运行目录。
- 原始运行日志。
- 失败截图。

备份前先停止应用，确保 SQLite 文件处于一致状态：

```powershell
docker compose stop
docker run --rm -v specchain-data:/source -v "${PWD}:/backup" alpine sh -c "cd /source && tar czf /backup/specchain-data-backup.tar.gz ."
docker compose start
```

备份文件和 `.env` 中的 `APP_ENCRYPTION_KEY` 必须一起妥善保管。只有数据库备份而没有原加密密钥时，项目中的敏感变量、GitHub/Gitee PAT 和模型 API Key 都无法恢复。

## 5. 升级

升级前：

1. 备份 `specchain-data`。
2. 保存当前 `.env`。
3. 确认没有正在运行的自动化任务。

更新代码后执行：

```powershell
docker compose build --pull
docker compose up -d
docker compose logs --tail 100 specchain
```

容器启动时会自动执行已提交的 Prisma 迁移。升级后应依次检查登录、项目切换、仓库连接、模型连接、三项 AI 默认模型、需求列表、测试用例脚本状态、一次主动脚本生成和一次自动化运行。

## 6. 日常检查

```powershell
docker compose ps
docker compose logs --tail 200 specchain
```

应重点关注：

- 容器健康检查是否通过。
- 持久化卷剩余空间。
- 执行任务是否长期停留在“排队中”或“运行中”。
- Chromium 运行是否出现内存不足。
- 30 天运行产物清理是否正常执行。

`@playwright/cli`、Playwright Test 和 Playwright 均由 `package.json` 与 `package-lock.json` 固定版本。构建镜像时只安装 Playwright 对应的一份 Chromium，页面探测和测试执行共同使用该浏览器。不要在运行容器中临时更新依赖；升级后应重新构建镜像。

## 7. 停止服务

停止并保留数据：

```powershell
docker compose down
```

不要使用 `docker compose down -v`，该命令会删除持久化卷及其中的数据库、日志和截图。
